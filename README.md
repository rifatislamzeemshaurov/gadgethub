# GadgetHub

A guardrailed AI gadget-shop advisor. Visitors ask about smartwatches, smart
TVs, laptops and cameras and get recommendations retrieved live from a Qdrant
product catalog — never answered from the model's memory. They can also upload
a product spec-sheet PDF to have it parsed and matched against catalog
alternatives.

| Layer | Stack |
|---|---|
| Backend | FastAPI + RAGWire + Qdrant, streamed responses (SSE) |
| Frontend | Next.js (static export) |
| Infrastructure | AWS ECS Fargate + ALB + CloudFront + S3, managed with Terraform |

The whole system deploys with a single script per environment. For local
development, the catalog ingestion flow and a full configuration reference,
see **[`gadgethub/guide.md`](gadgethub/guide.md)**.

## Configuration

Everything is configured in one file: **`gadgethub/.env`**. To start from
scratch, copy `gadgethub/.env.example` to `gadgethub/.env` and fill it in.

| Variable | Purpose |
|---|---|
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | AWS credentials used by the deploy/destroy scripts. Leave empty to use your `aws configure` profile instead. |
| `AWS_REGION` | Region the stack is deployed to. |
| `AWS_ACCOUNT_ID` | Safety check — deployment aborts if the credentials belong to a different account. |
| `PROJECT_NAME` | Name prefix for every AWS resource (`<PROJECT_NAME>-<environment>-*`). |
| `USE_CUSTOM_DOMAIN`, `DOMAIN_NAME`, `APP_SUBDOMAIN` | Serve the app at `https://<APP_SUBDOMAIN>.<DOMAIN_NAME>`. `DOMAIN_NAME` must already be a Route 53 hosted zone in the account; the DNS record and ACM certificate are created automatically. |
| `CONTAINER_CPU`, `CONTAINER_MEMORY`, `DESIRED_COUNT` | Fargate task size and count. |
| `OPENAI_API_KEY`, `OPENAI_MODEL` | OpenAI credentials and chat model. |
| `QDRANT_URL`, `QDRANT_API_KEY` | Qdrant Cloud cluster holding the product catalog. |
| `API_KEY_UI` | Shared secret the frontend sends as `X-API-Key`. |
| `CORS_ORIGINS`, `USE_S3`, `S3_BUCKET`, `MEMORY_DIR` | Local-run settings; set automatically in AWS. |

The only other env file is `gadgethub/frontend/.env.development`
(`NEXT_PUBLIC_API_URL`, `NEXT_PUBLIC_API_KEY`), which Next.js requires to live
inside `frontend/` for local development. `frontend/.env.production` is
generated by the deploy script.

## Prerequisites

1. **Tools**: `terraform`, `aws` CLI, `docker` (running), `uv`, `node`.
2. **`gadgethub/.env`** filled in (see above).
3. **Catalog ingested, once** — no product data ships in this repository. Drop
   your catalog PDFs into `gadgethub/data/`, open
   `gadgethub/ingestion/rag_pipeline.ipynb` and run the setup, staging and
   ingest cells. See `gadgethub/ingestion/ingest.md` for the PDF layout each
   category expects. Skip this if the `gadgethub-catalog-openai-qdrant`
   collection is already populated in the cluster `QDRANT_URL` points to.

## Deploy

```powershell
cd gadgethub
.\scripts\deploy.ps1 -Environment dev
```

Bash: `./scripts/deploy.sh dev`

One command builds the backend image, pushes it to ECR, applies the Terraform,
builds the frontend against the live API, uploads it to S3 and invalidates the
CloudFront cache. The first run takes a few minutes (CloudFront distribution
creation is the slow part) and prints the app URL when it finishes.

`-Environment` accepts `dev`, `test` or `prod`. Each one is a fully separate
stack with its own Terraform workspace and its own resources, prefixed
`<PROJECT_NAME>-<environment>-*`.

> The custom domain settings in `.env` apply to whichever environment you
> deploy. A hostname can only be attached to one CloudFront distribution at a
> time, so before deploying a second environment alongside the first, either
> change `APP_SUBDOMAIN` or set `USE_CUSTOM_DOMAIN=false`.

## Tear down

```powershell
.\scripts\destroy.ps1 -Environment dev
```

Bash: `./scripts/destroy.sh dev`

Empties both S3 buckets, then destroys every AWS resource for that
environment. Destroy `dev`/`test` when they are not in use — the ALB and
Fargate task cost roughly $25–30/month per environment whether or not anyone
is chatting. The Qdrant catalog is an external service and is never touched.

## Features

- **Grounded answers** — every product fact comes from a live Qdrant search in
  the same turn. Product cards in the UI are built directly from the retrieved
  data, not parsed out of the model's prose.
- **Streaming responses with live status** — the reply streams in as it is
  written, with real progress from the agent's tool calls (checking
  categories, searching the catalog, reviewing results).
- **PDF upload** — a spec sheet is parsed and matched against catalog
  alternatives. The file is read once and discarded; it is never written to
  the vector store.
- **New chat** — one click clears the conversation and starts a fresh session.
- **Category-aware metadata** — cameras, laptops, smart TVs and smartwatches
  each surface their own spec fields on every product card, matching
  `gadgethub/ingestion/rag_metadata.yaml` field for field.
- **Access control** — `/chat`, `/upload` and `/conversation/*` require the
  `X-API-Key` header to match `API_KEY_UI`, and `CORS_ORIGINS` restricts which
  origins may call the API.
